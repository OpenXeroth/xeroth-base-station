Build guide

Build a base station.

This is how XER2, the network's station at Timbavati, is built. It takes an afternoon to assemble and install, and then a day of recording to survey the antenna's exact position.

Parts

PartWhat XER2 usesNotes
ComputerRaspberry Pi 5Any 64-bit Debian or Ubuntu machine works. XER2 runs from a 64 GB microSD card.
Receiveru-blox ZED-F9P on an ArduSimple simpleRTK2B Lite boardAny ZED-F9P board with its UART1 pins brought out. Single-frequency receivers will not work.
Serial linkFTDI FT232R USB-serial cable, 3.3 VWired to the receiver's UART1: cable TX to receiver RX, cable RX to receiver TX, ground to ground. It must appear on the Pi as /dev/ttyUSB0.
AntennaSurvey-grade dual-frequency GNSS antennaFixed rigidly, with an unobstructed view of the whole sky. The station's accuracy is the antenna mount's accuracy: it must not move.
Power and networkMains, wired internetCapture carries on through network outages and uploads the backlog when the link returns.

1. Prepare the Pi

Write Raspberry Pi OS Lite (64-bit) to the card with Raspberry Pi Imager. In Imager's settings, make the user xeroth and turn on SSH. The software installs into /home/xeroth, so the name matters. Then, on the Pi:

sudo apt-get update
sudo apt-get install -y git build-essential python3 python3-serial curl

2. Build RTKLIB

The station records with str2str and converts to RINEX with convbin, both from the rtklibexplorer branch of RTKLIB. Build them from source and put them in /usr/local/bin, where the station looks for them:

git clone https://github.com/rtklibexplorer/RTKLIB.git ~/RTKLIB
make -C ~/RTKLIB/app/consapp/str2str/gcc
make -C ~/RTKLIB/app/consapp/convbin/gcc
sudo install -m 0755 ~/RTKLIB/app/consapp/str2str/gcc/str2str \
                     ~/RTKLIB/app/consapp/convbin/gcc/convbin /usr/local/bin/

3. Get the station software

git clone https://github.com/OpenXeroth/xeroth-base-station.git ~/xeroth-base-station
mkdir -p /home/xeroth/base_station/scripts
cp ~/xeroth-base-station/station-configs.example/example.conf \
   /home/xeroth/base_station/scripts/station.conf

Plug in the receiver. The first time the station starts it sets the receiver up itself: raw measurements once a second on UART1 at 115200 baud.

4. Survey the antenna

Corrections from a base station are only as good as the position it claims for its antenna, so that position has to be measured, once, to a centimetre or better. Record a full day from the receiver, convert it, and send it to a free processing service:

python3 /home/xeroth/xeroth-base-station/payload/scripts/ensure_receiver.py
str2str -in serial://ttyUSB0:115200:8:n:1:off -out file:///home/xeroth/survey.ubx
#   leave it running for at least 24 hours, then stop it with Ctrl-C
convbin -v 3.03 -r ubx -f 2 survey.ubx

That writes survey.obs beside the recording (some RTKLIB builds name it survey.rnx). Upload it to AUSPOS (Geoscience Australia, works worldwide) or to NRCan CSRS-PPP. Both email back the antenna position. Put its Cartesian coordinates, X Y Z in metres, on the coordinate line of station.conf, replacing 0.0000 0.0000 0.0000. XER2's line reads:

4974523.9720 3008024.3060 -2616592.1730

Until you have done this the station still records, but leaves the position out of its files.

5. Join the network

Apply as a station operator. When you are approved, your dashboard shows your station's identifier and its upload key, once. Put both in station.conf:

STATION_ID=XER3
UPLOAD_KEY=xrx_...

The key lets the station upload its own files and nothing else. The file is made readable by the xeroth user only when you install.

6. Install

cd ~/xeroth-base-station
sudo ./install.sh

The installer is safe to run again at any time. It starts capture, schedules the upload every minute, a watchdog that restarts capture if it stalls, and a disk guard that removes the oldest raw files when space runs low. To update, run git pull and the installer again.

7. Check it is working

systemctl status gnss-capture.service
tail -n 20 /home/xeroth/base_station/logs/automation.log

Within twenty minutes the log shows lines ending to https://base.xeroth.ai as XER3, one for each file, and your station appears with its position and last upload at /v1/stations.

The station can also report its health as JSON on port 8080, but only over Tailscale: install and sign in to Tailscale and gnss-health.service starts with the rest. Without Tailscale that one service does not start; capture and upload are unaffected.

If something is wrong

  • Capture is not running. journalctl -u gnss-capture.service -n 50. Usually the cable is not at /dev/ttyUSB0, or the wires to UART1 are crossed the wrong way.
  • Uploads fail with HTTP 401. The key in station.conf is wrong or revoked. Make a new station upload key on your dashboard.
  • Uploads fail with HTTP 403. STATION_ID is not the station your key belongs to.
  • Anything else. Open an issue or email open@xeroth.ai with the last 50 lines of automation.log.
